# Architecture\n\nThe product is split into a Next.js presentation layer and NestJS competition API. PostgreSQL is the durable source of truth and Redis is reserved for shared ephemeral state, pub/sub and distributed coordination.\n\nThe server owns the live-session state machine, deadline and scoring. Browser timers are visual only. Contestant clients never receive the correct answer before reveal.\n\nState machine: LOBBY → QUESTION → QUESTION_LOCKED → REVEAL → LEADERBOARD → QUESTION → FINAL_RESULTS → ENDED.\n\nAt 300 contestants the first production target is a single well-sized API instance. At larger events, run multiple API/WebSocket instances behind a load balancer with a Socket.IO Redis adapter and bounded PostgreSQL pools.\n
